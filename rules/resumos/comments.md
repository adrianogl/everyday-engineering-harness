## Comentários de código

Comentário só para regra de negócio, restrição, invariante ou decisão que o código não deixa óbvia, descrevendo o estado atual em uma a três linhas. Nunca histórico (card, commit, incidente, debugging, comportamento antigo), nunca narrar a próxima linha, nunca código comentado. TODO só com a condição concreta para remover. Antes de comentar, tente um nome melhor ou uma função extraída.
